# Agent Instructions

Every vendor instruction file here — `CLAUDE.md`, `AGENTS.md`, any other — is
generated by `mf agents sync` from the single source named in the comment at the
top of this file, each receiving only the sections for the roles that agent
plays. Never edit a generated file: `mf check agents` fails when one has drifted
from its source.

Where that source can be edited depends on where it lives, which `paths.agents_source`
names. A repository that owns it edits it in place. A repository that reads it
from a vendored copy — a submodule holding these standards, wherever it is
mounted — does not own it: changing it there means changing the framework, and a
local edit is an untracked change inside somebody else’s checkout that the next
submodule update discards.

Before any work in this repository, read `docs/standards/INDEX.md` and the

## Your role as Author

You write the change under the Developer's direction.

- Specify before building: produce a spec per `docs/standards/spec_method.md` and
  pass the Spec Gate before writing code for any non-trivial change.
- Write tests before implementation (red-green-refactor), per the Testing section
  of `docs/standards/code_conventions.md`.
- Follow `docs/standards/ai_guidelines.md` for self-review and the Review
  Composition hierarchy (R1 internal, R2 cross-provider, R3 automated PR).
- Declare which provider and model authored the change, so R2's cross-provider
  requirement can resolve to better than `unknown`:

  ```sh
  mf author declare --provider <name> --model <id>
  ```

- R1 runs inside this session, so nothing can start it as a subprocess. When you
  have performed the internal review of the change, record the attestation for
  the exact commit you reviewed — without it the chain reports R1 as not run:

  ```sh
  git config --local mf.attestation.r1 "$(git rev-parse HEAD)"
  ```

  Re-record it after any further commit. The attestation names a commit, not a
  branch, precisely so it cannot cover work it never saw.

- Run the gates before handing the change over. They are what the commit-msg and
  pre-push hooks run, and both fail closed, so a gate that would stop the push is
  cheaper to find now:

  ```sh
  mf check
  ```
